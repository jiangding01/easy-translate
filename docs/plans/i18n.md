# i18n 方案：界面语言跟随浏览器

> 2026-11-17 · 状态：已经过 Opus 对抗式审查（在副本中实测 WXT 构建与 Chrome 158 加载），按审查意见修订（见第 6 节）。用户已确定界面语言跟随浏览器，并授权按最佳实践决定细节。

## 1. 目标与范围

- 扩展的全部界面文案支持 **en**（默认）、**zh_CN** 和 **zh_TW**（第 6 批补齐）三种语言；**ja、ko 暂时不做**，等有用户或审校者时再加，届时只需新增一个 yml 文件。界面语言由 Chrome 按浏览器语言自动选择（`chrome.i18n`），不提供扩展内切换。
- 范围包括：
  - 工具栏面板、设置页；
  - 划词卡片、灵岛、页内渲染（「未译出」「重试」）；
  - 后台错误文案、引擎状态文案、右键菜单；
  - manifest 中的名称、描述、`action.default_title`、快捷键描述；
  - 所有 aria-label、title、data-tip。
- 不在范围内：
  - 翻译的目标语言、源语言，以及网页内容和译文本身；
  - 语言选择器里的语言名（见第 3 节）；
  - 日文、韩文界面；zh_HK 等未提供的语言回退到默认的 en。
  - 扩展内的界面语言切换。

## 2. 调研结论

- **文案约 250 条**：
  - 面板约 40 条，设置页约 120 条；
  - 后台与公共库约 50 条：`error-messages.ts` 32 条、`engine-view.ts` 15 条、右键菜单 2 条；
  - 按需模块约 46 条：卡片 27 条、灵岛 14 条、`render.ts` 2 条、`error-text.ts` 3 条；
  - manifest 3 条，另有 `name` 和 `default_title`。
  - 其中约 25 条有插值或复数，约 40 处是读屏和提示文案。
- **常驻内容脚本**（`content.ts`、`bootstrap.ts`、`selection/watch.ts`、`auto-start.ts`）里没有界面文案，常驻部分不需要引入 i18n。
- **既有约定**：
  - 最终方案选定 `@wxt-dev/i18n`；
  - 读屏文案要一起迁移；
  - 用户可见文案需要用户确认；
  - 错误文案的写法是「发生了什么 + 怎么办」；
  - 译文节点的 `lang` 跟随译文语言，不跟随界面语言。
- **FluentRead**（只借鉴思路）：
  - 借鉴：键名采用「模块.语义」；统一插值和复数写法；缺键时回退；按需模块不加载全量语言包；为语言包写校验。
  - 不借鉴：自建运行时（它支持用户自选界面语言）、旧中文反查机制。

## 3. 设计决定

| 决定 | 理由 |
|---|---|
| 使用 `@wxt-dev/i18n`（0.2.8，2026-10-04 发布），文案写在 `src/locales/en.yml`、`src/locales/zh_CN.yml`，构建时生成 `_locales` 和类型 | 官方方案；`t()` 有类型检查，键名写错时 typecheck 会失败；支持嵌套键、`$1` 插值和复数 |
| 扩展页面和后台用 `i18n.t()`；**按需模块不引入这个库**，用一个几行的辅助函数直接调用 `browser.i18n.getMessage`，键名由类型约束 | 按需模块体积紧张，而且必须是零 import 的单文件 |
| `default_locale: en` | 浏览器为中文时显示中文；其他语言显示英文比显示中文更合理，也符合开源惯例 |
| 语言选择器里的语言名保留自称（简体中文、English、日本語……），不翻译 | 语言选择器的通用做法；与已确认的「English → 简体中文」写法一致；`Intl.DisplayNames` 会输出「中文（中国）」这类形式 |
| 后台错误表改为「错误码 → 文案键」，后台用浏览器语言生成 `userMessage` 后经 Port 发给内容侧；内容侧 `error-text.ts` 的两条本地兜底也改为 `getMessage` | 后台和内容侧在同一个浏览器里，语言一致；完整错误表仍然不会进入内容脚本 |
| 每份 yml 增加 `meta.locale`（en / zh-CN / zh-TW），表示实际选中的语言包。数字格式（如 `CacheSection.tsx:45`）和扩展页面的 `<html lang>` 都以它为准，不用 `getUILanguage()` | 审查实测：浏览器语言为 zh_HK、de 等时，界面会回退到英文，但 `getUILanguage()` 仍返回浏览器语言，会出现「英文界面、数字按浏览器语言格式化」的错位 |
| 测试中用 `zh_CN.yml` 给 `getMessage` 打桩，在 `vitest.setup` 里统一提供 | 现有约 350 处中文断言基本不用改 |
| 新增 `scripts/check-i18n.mjs`，接入 `npm run check` 和 CI：① 非测试源码里不能出现汉字（白名单：正则、语言自称名、注释）；② en 和 zh_CN 的键完全一致；③ 同一键在两份文案中的占位符个数一致 | 防止又写进中文硬编码，防止漏翻 |
| check-build 增加断言：产物中存在 `_locales/en/messages.json` 和 `_locales/zh_CN/messages.json`，manifest 有 `default_locale`，`name`/`description`/`default_title`/commands 描述均为 `__MSG_*__` | 防止构建产物退化 |
| **不调整体积预算** | 审查实测：文案改成键名后体积下降（中文每字 3 字节）。selection-runtime 18.63→18.06KB，page-runtime 22.10→21.64KB，background 57.11→55.90KB（已包含 i18n 运行时约 0.40KB）。popup 和 options 各约增加 0.4KB |
| 英文文案由 Agent 起草，每批 PR 附「中文 \| 英文」对照表，用户抽查 | 约 250 条，逐条确认成本太高 |

## 4. 实施规则（审查后补充）

1. **按需模块的辅助函数**（`src/content/i18n.ts`，几行）：
   - 键名用 `keyof GeneratedI18nStructure` 约束，只从 `#i18n` 导入类型，内部把键名中的 `.` 转成 `_` 后调用 `browser.i18n.getMessage`；
   - **自带复数选择**：@wxt-dev/i18n 在构建时会把复数的两种形式用 ` | ` 拼成一条消息，直接调用 `getMessage` 会把两种形式一起显示出来；
   - 按需模块用到的键只能用 `$1–$9` 插值，不能用 `{name}`。
   - 键名表（如 `MODES`）用导出的 `NoArgKey` 类型；`message` 收到联合类型的键时只接受 `NoArgKey`，带插值的键必须以单个字面量调用，这样插值个数才能逐键检查。
2. **按需模块不在模块顶层取文案**：文案一律在函数内部获取，模块顶层只保留键名表。原因：check-build 用 vm 执行 runtime 时，环境里没有 `i18n`；同时也遵守「求值只注册工厂」的约定。`error-text.ts` 的 `LOCAL` 表、`isle.ts` 的 `MODES` 表照此改写。
3. **常驻内容脚本**（content.ts、bootstrap.ts、watch.ts、loader.ts、auto-start.ts）禁止引入 i18n 或辅助函数；check-build 断言常驻 `content.js` 不含 `getMessage`。`session.ts` 只被 bootstrap 类型导入，值导入只在 page-runtime，属于按需模块（第 2 批核实）。
4. **`languages.ts` 永远不接 i18n**：它同时用于 LLM 提示词，并且会打进常驻脚本。句子里嵌入语言自称（如「This text is already in 简体中文」）可以接受。
5. **品牌名不翻译**（Google Translate、DeepSeek、SiliconFlow 等）。预设名会写进用户配置，切换界面语言后不会跟着变，这是可以接受的。
6. **带内嵌元素的句子**（EngineItem「需要允许扩展访问 <host>」、popup「{引擎} {原因}，翻译已暂停」等）：用一个键加 `$1` 表示，渲染时按占位符拆开再插入 React 节点，不拆成前后两个键，以便各语言调整语序。
7. **扩展页面的 HTML**：
   - popup 去掉 `<title>`，否则会覆盖 `action.default_title`（审查实测）；
   - options 的标题在 main.tsx 中设置 `document.title`；
   - 两个页面的 `<html lang>` 都由 `meta.locale` 动态设置；
   - 划词卡片和灵岛的宿主元素也设置 `lang`，避免继承网页的语言。
8. **右键菜单**：除了 `onInstalled`，`runtime.onStartup` 时也重建，这样换了浏览器语言、重启浏览器后菜单会跟着变。
9. **后台错误表**：`FULL_COPY_TABLE_MARKERS` 改用只出现在「错误码→键」表中的键名作为标记，否则迁移后这项检查会永远通过。另外，popup 的 `page-session.ts` 的 `pausedReason` 表，以及散落在 6 处的 `describeError` 中文兜底，归入第 3 批处理。
10. **`check-i18n.mjs`**：
    - 用 TypeScript AST 扫描，按解码后的文本判断（`\u4e2d`、`&#20013;` 也算；正则字面量和注释自动跳过）；字符范围包括汉字、CJK 标点与全角空格、全角字符、假名、注音；
    - 扫描范围包括 `src/**/*.{ts,tsx,html}`、`wxt.config.ts`；HTML 的注释和 `<style>`/`<script>` 内的注释不计；
    - 豁免方式为**注释**里的 `i18n-ignore: 原因`（字符串内容不算），作用于注释所在行；注释独占一行时（含 JSX 的 `{/* */}`）还覆盖紧接的下一行，行尾注释只管本行；JSX 里写 `{/* i18n-ignore: 原因 */}`。目前用于 `languages.ts` 的语言自称、设置页「译文样式」里的示例译文（模拟网页上的译文，不是界面文案），以及 `codec.ts` 匹配的全角标点；
    - **基线模式**：第 1 批之后源码里仍有 287 条中文硬编码。`scripts/i18n-baseline.json` 记录这些字面量文本的哈希及出现次数（多重集，不绑定文件，所以移动、改名文件不受影响；一个模板字符串算一条，插值处记作 `{}`）。检查时每条字面量必须在基线里一一匹配，新增、改写或扩写的中文都会报出「文件:行」（例外：基线里出现多次的同一段文本，迁走一处后可以在别处原样再写一处，这是不绑定文件的代价）；基线里没被用到的条目（已迁走）会提示运行 `npm run check:i18n -- --update-baseline` 收缩。该命令只删不增，所以基线只减不增，第 4 批结束时应清零。基线结构不符时直接失败；首次创建用 `--init-baseline`，文件已存在时拒绝执行；
    - `src/locales` 下只允许 `<locale>.yml`；
    - 校验 en、zh_CN（以及以后的 zh_TW）的键集合一致，`$n` 编号集合一致；`meta.locale` 等于文件名（`_` 换成 `-`）；
    - 键名转成 `_` 并小写后不能互相冲突；键名每段只能是字母数字（不能含 `-`、`_`）；
    - 任何文案（包括复数的每种形式）不得含 ` | `（构建时它用来分隔复数形式）；不得为空；
    - 字面量 `$` 必须写成 `$$`；
    - 会被 YAML 改写的值必须加引号：` #` 截断、数字（含 0x/0o/0b、下划线）、布尔、日期；不用 `{ }`/`[ ]` 流式写法、锚点和标签。
11. **check-build**：
    - 产物 `_locales` 的目录与 `src/locales/*.yml` 一一对应（至少有 en、zh_CN），manifest 有 `default_locale`；
    - 解析 manifest 中所有 `__MSG_*__`，断言每个键在各个语言包里都已定义（审查实测：引用了未定义的键，Chrome 会拒绝加载）。
12. **测试桩**：在 vitest setup 文件**顶层**给 `fakeBrowser.i18n.getMessage` 赋值（模块级常量在 import 时就会求值，不能放在 beforeEach 里）。消息由 `@wxt-dev/i18n/build` 生成，与产物一致。桩要模拟 Chrome 的行为：
    - `$1–$9` 和 `$$`；
    - 缺少插值时替换为空串；
    - 键名大小写不敏感；
    - 缺键时**直接抛错**，让漏掉的键在测试中立刻暴露。
    - `@@ui_locale`、`@@bidi_*`、`@@extension_id` 按测试语言给出合理值。
13. **脚本与依赖**：`typecheck` 改为 `wxt prepare && tsc --noEmit`，保证类型和 yml 同步；`@wxt-dev/i18n` 放进 dependencies，让 `npm audit --omit=dev` 也覆盖到它。代价是它把 wxt、vite 等构建链也带进运行时审计：构建期依赖出了暂无补丁的公告时，经核实不进扩展包后，按公告 ID 写进 `scripts/audit-allowlist.json` 限期豁免（`scripts/check-audit.mjs`，2026-11-18 起，首条为 picomatch GHSA-fc5q-39xc-vjpf）。
14. **英文界面的设计点**：在第 4 批出效果图，再由用户确认：
    - 灵岛的单字按钮「双/译/原」，28px 宽，英文需要图标或缩写；
    - 无名自定义服务的简称「自」；
    - 英文文案更长，popup 宽 280px，需要做一次英文布局检查。

## 5. 分批实施（每批一个 PR，单独可合并）

**第 1–4 批之间不发版、不打 tag**：中间状态会出现半中半英（非中文浏览器下），全部完成后才能发 v0.2.0。中文浏览器不受影响。

1. **基建**：
   - 依赖、`wxt.config.ts` 模块、`default_locale`；
   - locales 骨架，含 `meta.locale` 和 manifest 文案（名称、描述、`default_title`、快捷键）；
   - popup 去掉 `<title>`，`<html lang>` 动态设置；
   - 测试桩、`check-i18n.mjs`、check-build 断言、`typecheck` 脚本；
   - 右键菜单在 `onStartup` 时重建；
   - 本方案文档。
2. **后台与公共库**（**已实现**，分支 `feat/i18n-batch2-background`）：`error-messages.ts`、`engine-view.ts`、`engine-options.ts`、`context-menu.ts`、`error-text.ts`，同时更新 `FULL_COPY_TABLE_MARKERS`。
   - 键名：错误 `errors.<类别>.<名称>`（`rate-limit` 写作 `rateLimit`）、兜底 `errors.generic`；引擎 `engine.*`。`error-text.ts` 与完整错误表共用同一组键，不再复制文案。
   - `BUILTIN_NAMES`、`NOT_READY_TEXT` 改为函数 `builtinName()`、`notReadyText()`；`UNNAMED_CUSTOM_NAME` 改为键 `engine.customFallback`。右键菜单复用 `manifest.commands.*`。
   - check-build：标记改为点号形式的键名，并断言 background 产物包含它们；新增常驻 `content.js` 不含 `getMessage`。
   - background 首次带上 i18n 运行时，迁移后体积仍下降（58.20→57.14KB）。基线 287→233。
   - 留给后续：无名服务简称「自」（第 4 批英文设计点）；`permissionMissing` 英文文案里的按钮名 "Grant access" 要与第 3 批设置页按钮的英文一致。
3. **面板与设置页**：popup、options，包括 `pausedReason` 和 `describeError` 的兜底文案、带内嵌元素的句子、数字格式、options 的标题。**拆成两个 PR**（方案经 Opus 审查：Mac 上 `--lang` 不生效、面板一处拼接、设置页分段控件定宽会溢出等已修正）：
   - **3a 面板**（**已实现**，分支 `feat/i18n-batch3-popup`）：`popup.*` 键与 3 个 `common.*`（自动检测、双语、仅译文）；`pausedReason` 改为取键；失败段数用复数键 `popup.failedCount`，数量按 `uiLocale()` 格式化（`failedText`，移到 `page-session.ts` 便于单测）；默认引擎还不能用时的提示由直接拼接改为 `popup.engineNotReady`（en「DeepSeek: No API key yet」）；句中「Google 翻译」一律引用 `builtinName('google')`。兜底文案复用 `errors.config.writeFailed`，新增 `errors.action.panelReadFailed`、`openSettingsFailed`。基线 233→189。
   - **英文布局检查**（总方案第 4.14 节第 3 项提前到本批）：Mac 上 Chromium 不认 `--lang`，界面语言跟随系统，所以截图用构建产物的副本，删掉 `_locales/zh_CN` 让扩展回退到英文，并断言 `meta_locale` 为 en；Chrome for Testing（Playwright 缓存）加 CDP 截图。`chrome.action.openPopup()` 能打开面板，但不会像点击图标那样授予 activeTab，面板读不到网页地址，只能显示「浏览器页面」状态。其余状态的长英文串改用实际字体测量：主按钮最长的「Use Google Translate this time」206px，按钮内可用约 220px；分段控件「Translation only」96px，每格约 120px。
   - **3b 设置页**（**已实现**，分支 `feat/i18n-batch3-options`；迁移由 Sonnet 子代理按方案完成，主会话审查）：142 条迁到 `options.*`，新增 `errors.action.addFailed/clearFailed/deleteFailed/connectFailed`；顶层表（`PAGES`、GeneralPage 各选项表、providers 的 `PRESETS`/`KEY_LINKS`/`TEST_BLOCKED_TEXT`）改存键名；授权句子用 `splitAround` + U+E000 拆分；缓存摘要抽成 `cacheSummary`（复数 + 数字格式）；标题由 `main.tsx` 设置；「Base URL」「API Key」标签也迁移（en 为 API URL、API key）。基线 189→47，剩下的全是第 4 批的按需模块。
   - **分段控件**：每段宽度不再写死 72px，改为 `minmax(var(--seg-min, 72px), 1fr)`（预览底色那组 84px），段内加 12px 左右内边距，英文长标签自动撑开、中文基本不变。滑块按网格第一格绝对定位，**网格线必须写全 `1 / 2`**：绝对定位元素的 `auto` 线是容器内边距边缘，只写 `grid-column: 1` 会让滑块铺满整个控件（截图测量发现，已修）。
   - **深色主题滑块**（用户反馈深色下选中态不明显）：深色下 `elevated`（0.21）只比 `surface`（0.20）亮 1%，滑块几乎看不见。新增 `--et-color-segment-thumb`、`--et-color-segment-ring`（浅色仍为白底加普通描边，深色为 0.30 底加强描边），设置页与面板的分段控件共用。没有采用琥珀描边：琥珀色留给样式卡片选中、主按钮和默认徽标，一页 5 组分段都加琥珀会抢视线，原生分段控件也是中性色凸起滑块。浅色截图前后逐像素一致。
   - **代码审查**（Opus，Deep）：无高严重度问题；按意见修了 `$name$` 扫描不全、英文下选中项加粗导致整组宽度跳动（`.segment` 改为纵向排列，用隐藏的 `::after { content: attr(data-label) }` 按粗体预留宽度，真实 Chrome 逐个点击各组宽度不变）、中文冒号、数字格式测试改用分组符不同的 `de` 验证语言参数。
