## 3. 视频、平台与信任边界

| 兼容事实 | 设计决策 | 归属 |
| --- | --- | --- |
| YouTube先非CC组后全轨，组内ASR优先 | 保留分组语义及对应UI说明 | 05 |
| HTML播放器fallback未再次核对videoId，音轨空token可能阻断后备 | 所有回退核对归属，逐级尝试有效上下文 | 05 |
| JSON3主路径与通用fallback分段不同 | 明确两套解析和ASR合并fixture | 05 |
| 字幕递归重试父Promise可能悬挂 | 有界循环并保证每次调用settle | 05 |
| 阅读逐句text键与文章时间文本键不同，外层旧缓存不含videoId | 新键分别包含视频、cue、语言及Prompt身份 | 06 |
| 文章最多3次调用，异常提前fallback，登录错误不fallback | 保留上限与例外，重发须通过统一预算和计费幂等门槛 | 06 |
| YouTube导出源SRT，TikTok另有TXT | 分别实现并按实际内容命名 | 05/07 |
| TikTok首轨首URL，HTML解析覆盖较少，未核video归属 | 首轨兼容，允许同轨URL回退，补归属和解析 | 07 |
| 页面桥可构造消息，旧反馈可携带嵌套密钥 | 窄桥、sender验证、脱敏预览、可信上下文提交 | 11/13 |
| 冲突扩展自动检查只读，手动失败可能被吞 | 新方案不引入管理其他扩展能力 | 11 |
| TTS关闭存在STOP代码路径，运行时到达未验证 | 显式停止、会话序号和运行状态验收 | 03/11 |
| 共享词典已有语言缺key直接key | 新设计跨语言查key回退，并显式记录变化 | 12 |
| Sentry调试函数读取标志后丢弃，无输出 | 开发诊断另设明确接口，设计意图不从空函数推定 | 11 |
