# 插件端覆盖状态

[返回总索引](README.md)

本页只讨论安装包内的插件端代码与功能。

## 能确认的覆盖

- 原包53个文件已全部保留，20个JS全部生成排版副本并校验哈希，源代码材料没有按功能裁剪。
- 已发现的插件主要功能均已有模块归属；当前13份模块文档包括网页翻译/还原、站点规则、划词/悬停/输入、浮球/键盘、截图/分享、YouTube字幕、字幕阅读/文章、TikTok文稿、设置/引导、专家/词库、账户客户端、缓存/队列、浏览器平台及国际化资源。
- 补查了后台/host/字幕脚本及popup/options中的核心消息注册、设置入口与已记录功能的对应关系，没有发现一个此前漏记的独立功能模块。
- 核心34项消息名称中，TikTok两项使用原生action监听，不是库的onMessage注册；`GET_ENABLE_PAGE_TRANSLATION`、`SET_ENABLE_PAGE_TRANSLATION`只在常量表出现，整个排版JS树未找到相应点属性访问。这两个名称不能算作另有未恢复的功能入口。

消息来源：[常量表](../evidence/legacy/extracts/platform/runtime-message-names.json)、[后台处理器LF9060](../evidence/legacy/formatted/background.js#L9060)、[TikTok原生监听LF9721](../evidence/legacy/formatted/background.js#L9721)、[host注册LF105977–106004](../evidence/legacy/formatted/content-scripts/host.js#L105977)、[设置路由LF2485](../evidence/legacy/formatted/chunks/options-kLkbiu2d.js#L2485)。

## 不能等同的结论

“代码材料完整保留、已发现功能均有模块归属”不等于“每一个业务函数、分支、配置组合和异常路径均已逐条写入文档并运行验收”。当前文件映射、摘录校验和入口对账不能证明后者。

插件端仍有明确的验证缺口：REA完整调用图是部分覆盖；运行证据目前是14项原视频逻辑探针和本轮5项视频/平台补充案例；尚未对完整旧插件逐项做浏览器交互/异常/站点回归；分享编辑器还存在包内资源缺失。因此不能声称插件端已达到逐分支100%文档覆盖或100%运行验证。

此前逐章节复核12份模块文档并交叉核对总览与路线图，详见 [全面复核报告](audit-report.md)。随后与DeepSeek的23篇文档对照，继续修正双方遗漏/错误，新增国际化资源模块及6项查词探针，详见 [交叉核验](deepseek-cross-validation.md)。这些是文档准确性审查，不会把有限探针或静态入口对账扩大为全行为覆盖声明。

后续按模块实施时，应把对应模块的每项验收用例、旧分支差异和已知缺陷逐一确认。原始代码与摘录会继续作为查证底本，不能仅凭现有说明文档就删除或忽略未解释的旧分支。
