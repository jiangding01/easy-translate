# Codex 评审核实（2026-11-18）

来源：Codex 两轮评审，2026-11-18。第一轮基于 main 的 `ea50ac4`，给出「当前项目的不足」7 条与「如果从零设计」5 条；第二轮基于 `feat/e2e-smoke` 的 `3fb8068`，复核我们的核实结论。核实由 Opus 子代理在隔离副本里读代码并写最小复现，主会话抽查。验证脚本 `editable.test.ts` 放在会话临时目录，仓库未改动。

## Codex 原文要点（精简转述）

不足 7 条：
1. P1：动态重扫可从编辑器或其后代开始，编辑区文字会进入整页翻译请求。建议初扫、重扫、发包前共用同一套祖先排除规则。
2. P2：退出「仅译文」时整份覆盖 style 属性，网页运行期间的样式更新被抹掉。建议只撤销扩展自己的修改。
3. P2：改全局默认引擎会影响已打开的整页会话。建议会话开始时固定实际引擎。
4. P2：初扫与动态监听之间有空窗。建议先监听、暂存变更，初扫后合并。
5. P2：缓存「保留 7 天」与实际删除行为不一致，清空失败仍提示成功。
6. P3：超过 5000 字符的段落无提示跳过。
7. P3：`<html lang>` 等于目标语言时，面板隐藏「翻译此页」与目标语言选择。

从零设计 5 条：
1. 先做可靠的阅读工具，用可见段落覆盖率、首段出译时间、恢复准确性验收。
2. 数据去向做成站点策略，全局默认只管新会话，优先本地翻译。
3. 双语只插入扩展自己的节点，仅译文复杂布局走独立阅读视图，精确撤销自己的修改。
4. 会话有一份明确状态，面板与灵岛读同一份，段落状态区分待译、已译、失败、跳过。
5. 真实 Chrome 回归测试提前，并拆分近 2000 行的划词卡片实现。

## 从零设计 5 条的采纳判断

1. 部分采纳。恢复准确性已在 e2e P0 第 3 条；「可见段落覆盖率」可作为 e2e 断言；缩小产品范围不采纳（与 M3 路线冲突）。
2. 部分采纳。M3d 站点规则可加「站点用哪个引擎」；「默认引擎只用于新会话」即第 3 条修法；隐私分级、本地优先留给 M3e。
3. 部分采纳。精确撤销采纳（第 2 条）；独立阅读视图不采纳（与 dom-contract 的 `data-et-only` 约定冲突，范围过大）。
4. 部分采纳。面板与灵岛已读同一份 PageState；可补「跳过」计数与固定引擎；「当前区域已译」暂不做。
5. 已在做。e2e 方案覆盖大部分；PR2 补编辑区隔离、样式精确恢复、扫描期间插入内容三类。`card.ts` 虽有 2008 行，但已有 1722 行单测，拆分不急。

## Codex 复核（同日，基于 `3fb8068`）

- 7 条与我们的核实一致：第 1、2、5、6 条用旧验证用例在隔离副本复现；第 3 条请求行为复现；第 4、7 条按源码确认。
- 新增建议并入排期：
  - e2e PR2 的两条关键断言写成「整页动态重扫时编辑区文字始终不出现在翻译请求里」「网站在翻译期间主动改的行内样式，退出仅译文后保留」。划词输入框反例不能代替前者。
  - M3d 站点规则：开启「总是翻译此站」时显示该站将使用的服务；面板与灵岛显示当前页实际使用的引擎（与第 3 条固定引擎一起做）。
  - 改渲染方式时保住 dom-contract（`et-tr` 等）这条对外接口。
- 不采纳：独立阅读视图（理由同上）。
